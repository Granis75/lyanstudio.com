01 / CONTEXT

The problem
behind the interface.

A retailer cannot afford to lose a sale, corrupt inventory or depend on a remote API at the counter. AlCaisse keeps the register, stock and cash sessions on the Windows computer, with local data storage.

Cash session→Barcode→SQLite sale→Stock movement→Receipt→Close session

03 / HOW IT WORKS

Built for the Windows counter.

AlCaisse is built with Electron, React, TypeScript and SQLite. Sales, inventory updates and cash-session records are stored locally, so the checkout workflow is designed to continue without an internet connection.

The desktop project also includes receipt-printing adapters and local backup tools. Printer and cash-drawer compatibility depends on the physical equipment and has not been independently validated.

A packaged Windows version has been inspected and tested locally by the developer. The executable belongs to a private client project and is not distributed on this website.

04 / WEB SIMULATION

Try the workflow online.

The interactive browser simulation lets you explore fictional checkout, stock and cash-session scenarios. It is separate from the Windows application: it does not process real payments, use the desktop SQLite database or connect to a receipt printer.
